# Implementation Plans

Generated by the `improve` (deep audit) skill on 2026-07-03, against commit
`b5f98ba`. Eight parallel read-only auditors (correctness, security,
performance, tests, tech-debt, deps/DX, docs, direction) surveyed the whole
workspace; every finding below was re-read and confirmed by the advisor
before it became a plan.

**Full findings inventory: [FINDINGS.md](FINDINGS.md)** — every finding across
all eight categories (severity, evidence `file:line`, confidence) plus the
direction options and rejected items, cross-referenced to the plan numbers
below. This README is the execution index; `FINDINGS.md` is the searchable
"what + where."

Execute in the order below unless a plan's **Depends on** says otherwise.
Each executor: read the plan fully before starting, run its **Drift check**
first, honor its **STOP conditions**, and update your row in the table when
done.

**One repo-wide fact every plan relies on** (inline, because executors have
zero context): ruxel is a Rust drop-in replacement for `ansible-playbook`
targeting exactly 16 known playbooks on 6 **production** servers. The closed
spec is normative (`docs/SEMANTICS.md`); unknown module/param/value = hard
parse error *by design*. Never connect to, resolve, or probe the six
production hosts (pegasus, delorean, titan, sentry, postgresql-nova,
clickhouse-selene) — see `AGENTS.md`. All development/testing runs against
disposable fixtures only. Quality gates before any commit:
`cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings`,
`cargo test` (or `cargo nextest run`).

## Cross-cutting theme (read before starting the P1 cluster)

The **convergence ledger is both the headline feature and the most dangerous,
least-tested subsystem.** Four independent silent-drift bugs (plans 006/008)
let a *drifted production host* report `ok (ledger)` and never re-converge —
the exact opposite of the tool's promise. Two intent docs (`GOAL.md`,
`RESTORE.md`) also *oversold* two capabilities the code does not deliver:
"secret lookups memoized to a handful of `op` calls" (they are serial and
lazy — plan 021) and "all four postgresql_privs shapes idempotent, rerun
changed=0" (`default_privs` is hardcoded always-changed — plan 011). Treat the
code, not those two docs, as ground truth for those two claims.

## Findings considered and rejected

- **"Support more Ansible modules/params/features."** Anti-goal: the closed
  spec (`docs/WORKLOAD.md`) and `AGENTS.md` forbid surface beyond the 16
  playbooks. Not a finding.
- **Cross-task batching of shell/command (e.g. the 36 identical restarts).**
  Rejected: `docs/ARCHITECTURE.md:172` fixes apt as the *only* cross-task
  merge and §6 classes creates-less shell/`restarted` as mandatory
  always-execute. Batching them would violate a recorded design decision and
  the honesty rule.
- **Warm-daemon `--resident` tier + drift dashboard now.** Deferred by design
  (`docs/PLAN.md:164`) until the ephemeral path is proven in M5. Plan 023's run
  log is the correct incremental substrate; do not build the daemon yet.
- **Autonomous `setup-*` gate sweep.** Blocked on the operator dropping a
  read-only ChainArgos deploy key into the `ruxel-test` vault
  (`RESTORE.md:84-93`); out of autonomous scope. Plan 025 captures the gates
  that need no key.
- **Frame-per-message buffering allocation, `frame.rs`.** Considered and
  dismissed: fine at realistic KB-scale payloads under the 64 MiB cap.
- **`ledger.json` vs the redb store `ARCHITECTURE.md:180` mentions.** The doc
  hedges "(or equivalent single-writer)"; JSON+flock qualifies. Only the
  durability gap (plan 007) and at-rest exposure (plan 008) are real; the
  format itself is not a finding.
